# Java OOP Pattern Lab — 

Python + PyQt6で、**実際のJava実行から取得した記録**を再生するデスクトップ教材です。
参照と同一性、Strategy、State、Observerの4教材に、正常例と比較例を各1つ収録しました。
23パターン対応版や汎用Javaデバッガではありません。

## 起動（Ubuntu / Linuxを想定）

Python 3.10以降を用意して、展開したディレクトリで実行します。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pattern_lab
```

または `bash run.sh`。パッケージ全体を同じディレクトリ構成で保持してください。
同梱記録の再生にJDKは不要です。**「Javaで再実行」にはJDK 17以降**が必要です。
Ubuntuなら `sudo apt install openjdk-17-jdk` で導入できます。
Qtのウィンドウ表示には通常のデスクトップ環境が必要です。
Linuxでxcbの依存関係エラーが出る場合は `libxcb-cursor0` 等の不足ライブラリをエラー内容に従って導入してください。
日本語が四角になる場合は、日本語フォント（例: `fonts-noto-cjk`）を導入してください。

検証環境: Python 3.12.14、PyQt6 6.11.0、Qt 6.11.0、OpenJDK 17.0.20、Linux x86_64。
PyQt6なしでも、コアの検証とJava実行評価は標準ライブラリだけで動きます。

## 使い方

1. 上部で教材と正常例／比較例を選びます。同梱記録の入力は100です。
2. 「次へ」「戻る」、スライダー、履歴のクリックで観測点を移動します。
3. 実線はオブジェクトが保持する参照、橙の破線は現在記録されている呼び出しです。
4. 「Javaソース」は、記録とソースのSHA-256が一致する場合に観測行を強調します。
5. 「全記録の検証」は現在位置にかかわらず記録全体を評価します。行をクリックすると根拠の観測点へ移動します。
6. 「正常例との比較」は同じ入力の両実装を、チェックポイント名で比較します。
7. 入力を変える場合は、0〜10000を指定して「Javaで再実行」を押します。両variantを実行します。Stateは固定シナリオなので数値入力を使いません。
8. JSON Linesの記録を保存・読み込みできます。外部から読み込んだ記録だけでは、対となる比較記録は用意されません。

「比較例」はJavaとして不正なコードという意味ではなく、**この教材の要求に違反する実装**です。
例えば参照教材の `b = new Box()` はJavaとして合法ですが、「aとbが同じBoxを参照する」という課題を満たしません。

### 判定の読み方

- 観測整合性: Pythonで再構成した状態と、Javaオブジェクトを直接読んだチェックポイントが一致するか。
- 教材契約: 指定した課題の条件を、その有限の記録で満たすか。
- PASS: 対象となる観測／契約を満たす。
- FAIL: 対象となる観測／契約に不一致がある。
- UNKNOWN: 完了記録や必須観測点が不足している。

誤実装を忠実に表示した場合、**観測整合性PASS・教材契約FAIL**が正しい結果です。
学習効果やJavaプログラム一般の正しさを示す指標ではありません。

## 評価を再実行

```bash
# コアと、インストール済みならGUIの検査（offscreen）
python -m unittest discover -s tests -v

# 同梱8記録の再評価（JDK不要）
python evaluate.py --out results/my_replay

# JDKによる26シナリオの評価
python evaluate.py --live --out results/my_live

# 一つの記録の検証
python -m pattern_lab --validate traces/observer_broken.jsonl

# Javaソースを変更した後、同梱8記録を更新
python -m pattern_lab --regenerate
```

生成済み結果は `results/pilot_live/` にあります。
26シナリオで86チェックポイントが一致し、正常13・比較13を所期の判定に分類しました。
異なる誤りが13種類あるわけではありません。誤実装は4種類で、うち3教材は複数入力で実行しています。
保持した未知実装の評価ではなく、開発用コーパスのスモーク評価です。

## 構成と変更場所

| 場所 | 内容 |
|---|---|
| `pattern_lab/core.py` | スキーマ検証、状態再構成、契約判定 |
| `pattern_lab/runner.py` | 同梱Javaの起動・タイムアウト・ソースハッシュ |
| `pattern_lab/gui.py` | PyQt6の画面と操作 |
| `java/PatternPilot.java` | 教材と手動計測、直接観測スナップショット |
| `lessons/*.json` | 日本語解説、問い、役割、宣言型の注釈 |
| `traces/*.jsonl` | 同梱のJava実行記録8件 |
| `evaluate.py` | 入力別実行、CSV/JSON出力、コアの時間・メモリ測定 |
| `tests/` | 欠損・整合性・再生・GUI操作の検査 |
| `docs/java_oop_pattern_visualization_plan.tex` | 独立した卒研計画・実装報告・今後の課題 |
| `docs/TRACE_FORMAT.md` | イベント仕様と境界 |

解説・問い・役割の変更は `lessons/*.json` で行えます。
**新教材の追加はまだJSONだけでは完結しません。** Java教材、LESSONS、契約関数等の変更が必要です。
この変更範囲を小さくする設計は、実験者が取り組む今後の研究課題に位置付けます。
Javaソースを変更した後は、記録再生成、テスト、評価を再実行してください。

## 既知の範囲と制約

- 同梱・単一スレッドの小規模教材のみ。Javaの全命令、ローカル変数、スタック、GCは観測しません。
- 呼び出しイベントは手動計測であり、JVMからの網羅的な自動取得ではありません。
- スナップショットは実オブジェクトから反射で取得しイベント列を参照しませんが、ID・値変換の補助部は共有します。
- source行は計測呼び出し位置です。隣接する複数処理を1行ずつステップ実行する機能ではありません。
- 型の表示は実オブジェクト型と教材注釈によります。任意コードの型検査機能ではありません。
- 整数演算はJavaで行います。Python側の一般Javaインタプリタはありません。
- 後退は先頭からの再生です。長大な記録には効率的ではありません。
- 対象パターンの自動認識、コード編集IDE、静的UML自動生成、変更影響の自動算出は未実装です。
- 教材契約はPythonに直接記述しています。汎用契約DSLは未実装です。
- Java再実行は同梱ソースだけを対象とします。改変したソースは利用者自身が信頼できるものを使用してください。
